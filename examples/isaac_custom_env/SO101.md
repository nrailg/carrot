# 换成 SO101，究竟要改什么？

有两条路线：**用官方 SO101 完整项目学习实物任务**，或**把你准备的 SO101 USD 接入这里的
最小 reach 任务**。本目录未附带 SO101 资产，也没有宣称 SO101 仿真已跑通。

## 1. 先看官方已经提供的 SO101 项目

完整教程网址：
[Isaac Lab SO101 Tutorial](https://isaac-sim.github.io/IsaacLab/develop/source/setup/tutorial.html)。

配套代码：
[isaac-sim/IsaacLabTutorial](https://github.com/isaac-sim/IsaacLabTutorial)。

这是 SO101 把小瓶放入架子的任务，包含机器人/物体资产、状态和相机观测、任务配置及学习流程。
如果你已经确定要使用 SO101，它比从 CAD、URDF、驱动参数全部手工重建更合适。
以上是官方项目提供的内容，不是本目录已完成的验证。

该项目的 `main` 使用自己锁定的较新 Lab 和 Newton 配套环境；本目录示例使用 Beta 2 的
Sim/PhysX API。**分别建环境，遵循各自的锁文件**。本例不会把最新项目中的 import
直接放进较旧环境，再宣称兼容。

源码阅读路线：

| 问题 | 官方文件 |
| --- | --- |
| 机器人有哪些关节、初始姿态和驱动？ | [Lab 的 so101.py](https://github.com/isaac-sim/IsaacLab/blob/develop/source/isaaclab_assets/isaaclab_assets/robots/so101.py) |
| 场景、动作、观测怎么组装？ | [任务 env_cfg.py](https://github.com/isaac-sim/IsaacLabTutorial/blob/main/src/isaaclab_tutorial/tasks/place_vial/config/so101/env_cfg.py) |
| 成功、奖励、reset 如何实现？ | [任务 mdp 目录](https://github.com/isaac-sim/IsaacLabTutorial/tree/main/src/isaaclab_tutorial/tasks/place_vial/mdp) |

核对当天官方配置里，SO101 手臂有五个主动自由度，加一个夹爪关节。
因此不能直接照搬 Panda 的七关节动作，也不能假设可精确实现任意六维末端位姿。
本例只要求到达三维位置，作为第一个任务比较容易理解；可达范围仍需实际检查。
依据：[官方 SO101 配置说明](https://github.com/isaac-sim/IsaacLab/blob/develop/source/isaaclab_assets/isaaclab_assets/robots/so101.py)。

## 2. 用自己的 USD 接入本例

从 [Importing a New Asset](https://isaac-sim.github.io/IsaacLab/v3.0.0-beta2/source/how-to/import_new_asset.html)
导入你的 URDF/MJCF 或使用已有 USD，再按
[Writing an Asset Configuration](https://isaac-sim.github.io/IsaacLab/v3.0.0-beta2/source/how-to/write_articulation_cfg.html)
检查机器人。需要准备：

| 内容 | 为什么需要 |
| --- | --- |
| 正确的 follower 资产及全部 mesh 引用 | SO100、SO101、leader/follower 不能混用 |
| 米制尺寸、质量/惯量、碰撞几何 | “能显示”不等于“物理正确” |
| 固定基座、正确的 articulation root | 机械臂不能把基座当成自由落体 |
| 关节名、限位、方向、默认姿态 | 代码的名字和数值必须与实际 USD 匹配 |
| 位置驱动的 stiffness/damping/力矩及速度限制 | 关节目标需要驱动器才能产生运动 |
| 末端刚体名或 TCP 定义 | 任务要知道测量哪个点的位置 |

[custom_arm.py](custom_arm.py) 的 `make_custom_arm` 读取 USD 中已有的驱动参数。
它不会自动生成正确的 SO101 参数；USD 若没有调好的 drive，应先根据官方机器人配置或
你自己的标定补齐。这个 helper 面向简单位置驱动机械臂；若资产有被动关节、mimic 关节或
特殊 actuator，应改成逐组配置，不要直接把所有关节都设为独立电机。

在 `run.py` 中 AppLauncher 启动后的 import 区域加入（出处：上面两个官方资产教程）：

```python
from custom_arm import make_custom_arm
from reach_env_cfg import configure_robot
```

然后在 `cfg = ReachEnvCfg()` 之后、创建 `env` 之前调用下面的替换接口。
**下面是需要填入你自己资产信息的接入模板，不是可直接粘贴运行的 SO101 配置。**
路径、默认关节角、末端名和可达范围都需要从选定的资产确认，不能凭机器人产品名猜测。

```python
# 官方模式：ArticulationCfg + JointPositionActionCfg + SceneEntityCfg。
# 教程：https://isaac-sim.github.io/IsaacLab/v3.0.0-beta2/source/how-to/write_articulation_cfg.html
# robot_usd / joint_defaults / arm_joint_names / ee_body / goal_ranges 是你确认好的数据。
robot = make_custom_arm(robot_usd, joint_defaults)
configure_robot(
    cfg,
    robot=robot,
    arm_joint_names=arm_joint_names,
    ee_body=ee_body,
    goal_ranges=goal_ranges,
)
cfg.actions.arm.scale = 0.05  # 本例建议的初次小幅试动值，单位 rad；不是电机标定值。
```

`configure_robot` 是本目录实现的便捷函数，其数据格式为：

- `robot_usd`：本地完整资产的绝对路径字符串。
- `joint_defaults`：`{真实关节名: 默认位置}`，包括夹爪；转动关节为 rad，移动关节为 m。
- `arm_joint_names`：按动作输出顺序排列的手臂关节名列表，夹爪不放在这组 reach 动作里。
- `ee_body`：对应实际 rigid body 的名字，不是任意末端 Xform 的名字。
- `goal_ranges`：`((xmin, xmax), (ymin, ymax), (zmin, zmax))`，基座坐标系，米。

原理出处为 [S3/S4](SOURCES.md#s3)：替换函数会同步修改机器人、动作关节、观测关节、目标 body、
奖励 body 和成功 body。仅改 `cfg.scene.robot` 会留下 Panda 名字，环境初始化就可能失败。
确认初始 reset 没有碰撞后，先用 `--policy hold --num_envs 1`，再试 `wiggle`。

五关节 reach 的动作是 `[N, 5]`，当前观测设计为 `[N, 22]`（5+5+7+5）。
要做抓取，再增加夹爪 action 和观测；实机的角度编码/归一化也应单独转换，不能直接当 rad。

## 3. 新手第一轮检查应看到什么

1. 机器人比例正常，基座固定，没有部件掉落或持续爆振。
2. 程序打印的 `joint_names`、`body_names` 与绑定一致。
3. 单关节小幅动作只驱动预期关节，方向和幅度符合定义。
4. 目标坐标位于该机器人可达区域，距离是在同一参考系下计算。
5. 超时能恢复初始状态；成功判据用手动或脚本构造的已知状态分别检查 True/False。
